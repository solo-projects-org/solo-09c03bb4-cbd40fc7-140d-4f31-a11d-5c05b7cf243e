# 灌装线欠重累计复检

灌装线每次少装几克，连续下来就要复检。本系统上传「抽检序号 + 整数克重」CSV 存入
SQLite，按序号顺序把 **(499 − 实测克重)** 计入累计，累计 **< 0 归零**；累计 **≥ 20 克**
时记录一条复检事件（本轮累计转正起点序号 → 触发序号、累计克数），随后清零。

## 运行

```bash
docker compose up --build        # 打开 http://localhost:5000
```

数据保存在名为 `filling-data` 的卷里（容器内 `/data/filling.db`），重启、失败后不丢。
不用 Docker 也可以本地跑：

```bash
pip install -r requirements.txt
python app.py                    # 默认 ./filling.db，可用 FILLING_DB 指定路径
```

## CSV 格式

两列：`抽检序号,整数克重`，首行表头可省。可上传文件或在网页上粘贴。

- **同号可更正**：已存在的序号再次上传即覆盖克重并触发复算；
- **新号只往后追加**：新序号必须大于当前最大序号，否则整批拒绝；
- 文件内序号不得重复；序号、克重必须为非负整数（序号 ≥ 1）。

## 复算策略（增量）

每次上传一个事务，重量与复检清单一同生效：

1. **跳过首处改动前的称重**：从首个改动序号起算，改动前的累计值/本轮起点直接取
   `run_state` 中保存的状态；
2. **汇合即沿用**：复算途中若已越过全部更正、当前序号仍是旧数据，且（累计值， 本轮起点）
   与旧结果一致，则之后的旧状态与旧复检事件原样保留，不再重读重量；
3. 若旧末尾之后还有本次新增的序号，则从旧末尾状态继续处理新增部分。

每批次的复算起点（`first_changed`）与沿用点（`resumed_at`）记录在 `batches` 表，
网页「批次记录」可见。

## 并发与持久化

- 进程内全局锁 + `BEGIN IMMEDIATE` 写事务：并发上传按生效顺序串行处理；
- 每批要么整体生效要么整体回滚，失败不影响最近一次成功结果；
- SQLite（WAL）落盘，重启后最近一次成功结果仍可查。

## 接口

| 方法/路径 | 说明 |
| --- | --- |
| `GET /` | 网页：当前累计、复检清单、最近称重、批次记录、上传表单 |
| `POST /upload` | 表单上传（文件或粘贴文本） |
| `POST /api/upload` | CSV 正文上传，返回 JSON（成功 200 / 数据问题 400） |
| `GET /api/state` | 当前累计、本轮起点、最近序号、计数 |
| `GET /api/events` | 复检清单（按触发序号排序） |
| `GET /api/weighings?limit=` | 称重记录 |
| `GET /healthz` | 健康检查 |
